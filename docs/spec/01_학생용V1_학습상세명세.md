# 학생용 V1 학습 설계 구현 명세

작성 기준: 2026-10-17. 이 문서는 개발 프롬프트에 병합할 학습 설계 지시다. 기존 교재 원고는 변경하지 않는다. 아래 추가 활동·재평가 문항은 구현 및 검수할 설계안이며 이미 제작·효과 검증된 콘텐츠로 표시하지 않는다.

## 1. 구현 범위와 현재 자료의 정확한 수

학생이 혼자 학습하는 V1을 구현한다. 오늘 학습, 전체 과정, 개념별 학습, 복습, 실전 연습, 개념 노트, 내 성장이 대상이다. 교사·관리자·반·과제 배포·학교별 기출 분석 화면은 V2이며 V1 메뉴나 빈 버튼으로 만들지 않는다. 콘텐츠 검증·가져오기·버전 관리는 데이터와 개발용 검사로 지원하되 학생 UI에 관리 기능을 노출하지 않는다.

| 현재 확보한 범위 | 정확한 수와 해석 | 구현 근거 |
|---|---|---|
| 교재 01~06 | 고유 성취기준 31개, 282문항 | `outputs/교재/01_과학의기초.md`~`06_과학과미래사회.md` |

교육청 245문항에는 출처·공식 정답·핵심 추론·오개념 후보·선수 개념·PDF쪽수 기록이 있다. 그러나 현재 학습 기록 스스로 모든 문항의 선지별 심층 분석·대안 풀이·단계 힌트·전이 문항은 추가 보완 대상이라고 명시한다. `indexed`, `analyzed`, `student_ready`, `published`를 분리하고, 데이터에 등록했다고 학생용 심층 해설이 완성된 것으로 표시하지 않는다. 평가원 37문항의 09·10 상세 풀이도 단계 힌트·독립 전이 문항·활동이 자동으로 완성되는 것은 아니다.

## 2. 교재를 줄이지 않고 단계로 전환하는 규약

성취기준 하나를 긴 한 화면으로 표시하지 않는다. `course → domain → standard → concept → learning_step`을 사용한다. 한 `learning_step`에는 한 가지 목표와 그 목표에 필요한 설명·그림·판단 활동을 연결한다. 긴 설명은 문단 사이 의미가 완결되는 곳에서 다음 단계로 나누며, 필요한 설명 자체를 줄이지 않는다. 화면 높이·글자 수를 맞추려고 조건·예외·중간 계산·예시를 삭제하지 않는다.

31개 성취기준마다 선개념→개념→개념평가→심화개념→심화평가→수능대비 전략→수능대비평가의 전체 경로가 남아 있어야 한다. 개념별 세부 단계는 이 순서 안에 배치한다. 아주 작은 모든 용어마다 일곱 단계를 억지로 반복하지 않는다. **교재의 필수 심화개념·심화평가는 핵심 과정의 일부이며, 선택 하이탑 확장 창과 별개**다.

원고를 Markdown AST로 읽어 문단, 목록 항목, 표의 셀, 수식, 이미지, 그림 읽기 설명, 문항 조건, 보기, 선택지, 정답·해설을 보존한다. 문항 정답은 제출 전 학생용 응답에 섞이지 않게 별도 저장한다. 편집자 출처 기록과 이미지 재제작 프롬프트는 제작 메타데이터로 보존하며 학생에게 공부할 본문처럼 노출하지 않는다. 이 이동은 삭제와 구별해 원문 대조 장부에 기록한다.

필수 데이터:

```ts
type SourceBlock = {
  blockId: string; sourceFile: string; sourceVersion: string;
  headingPath: string[]; startOffset: number; endOffset: number;
  exactTextHash: string; sourceKind: 'teaching'|'question'|'solution'|'figure'|'editorial';
  standardIds: string[]; conceptIds: string[];
};
type Step = {
  stepId: string; conceptId: string;
  stage: 'prerequisite'|'concept'|'concept_check'|'advanced'|'advanced_check'|'strategy'|'exam_check';
  sourceBlockIds: string[]; contentVersion: string;
  bodyBlockIds: string[]; interactionIds: string[]; questionIds: string[];
  prerequisiteSkillIds: string[]; targetSkillIds: string[];
  nextStepId: string|null; remediationRoutes: Record<string,string>;
  completionRuleId: string; optionalTrackId: string|null;
};
```

`coverage_manifest`는 원문 block마다 학생 본문 단계, 정답 해설, 제작 메타데이터 중 정확한 목적지를 하나 이상 가진다. 한 block을 여러 화면에서 참조할 수 있으나 내용의 사본을 따로 고치지 않는다. block을 더 작게 나누면 원문 offset 구간이 공백 없이 덮이는지 검사한다. 원문↔단계의 양방향 추적을 제공하고, 새 버전에서 block이 이동해도 학습 기록의 식별자는 유지한다. 행 번호만을 영구 식별자로 사용하지 않는다.

가져오기 완료 조건은 (1) 원문 block 누락 0, (2) 291+37 문항 ID 누락·중복 0, (3) 각 문항의 모든 요구·선지→근거 block 연결, (4) 진단을 제외한 평가의 필요한 근거가 권장 경로상 선행, (5) 표·수식·도판·그림 읽기 설명이 실제 렌더링됨이다. ‘전체 원문 보기’ 다운로드만 남기고 기본 단계에서 설명을 뺀 것은 미완료다. 원문 전체 보기와 검색·해설 링크는 추가 접근 수단이다.

문단 수만 같으면 충분하다고 판정하지 않는다. 각 세부 개념의 `definition, prerequisites, conditions, causalSteps, workedExample, unitsAndDataReading, misconceptionAndCounterexample`을 실제 source block과 연결하고 해당 문항의 요구가 어느 요소를 사용하는지 기록한다. 문장 해시 일치 검사는 전송 누락을 찾는 도구이며 개념 설명의 충분함 자체를 증명하지 않는다.

## 3. 첫 학습, 선수 보충, 막혔을 때의 복구

첫 화면에서 시작할 개념과 추천 이유를 알려 주고, 긴 중학교 전체 시험을 선행 조건으로 만들지 않는다. 선개념은 해당 고교 개념에 실제 필요한 기능만 진단한다. 중학교 연결색인의 단원 전체가 의무 선수 범위라는 뜻으로 해석하지 않는다.

선수 연결은 `outputs/중학교과학_선수개념_연결색인.json`의 31개 `integrated_science` 연결과 45개 `diagnostic_questions`를 사용한다. 중1·중2는 2022 판본, 중3은 2015 판본이며 `2old:7-1`, `2old:7-2`는 추가된 2015 중2 수권이다. 같은 번호의 새 중2 전기 단원과 합치지 않는다. `boundary_or_gap`과 `limits`를 그대로 보존한다. 새 중3 대기대순환·북태평양 표층순환의 인과 연결 및 계절별 우리나라 주변 해역 수온·염분 자료 본문은 별도 미확보라고 기록되어 있으므로 ‘모든 중학교 자료 완비’로 표시하지 않는다.

보충 화면은 정의→구체 예→그림/표 읽는 법→한 단계씩 계산/추론→학생 재확인의 구조를 갖춘다. 개념 링크 하나나 ‘중학교 복습하세요’만으로 완료하지 않는다. 중화 선수는 `2:4-2`, `3:1-1`, `3:1-2`, `1:3-1`의 이온·반응식·비례·온도와 열이며 산성/염기성·지시약의 초등 배경도 짧게 확인한다. pH 로그·몰농도 계산을 필수 진입 조건으로 추가하지 않는다.

보충 이동 전 `returnContext={stepId, questionId, instanceId, draftAnswer, scrollAnchor, reason, contentVersion}`를 저장한다. 보충 완료 후 원래 문제에 복귀하고 초안을 복원한다. 원래 답 수정은 학습 기록이며 독립 숙달 근거로 세지 않는다. 이어 다른 조건의 확인 문항을 제공한다.

오답 원인을 한 번에 확정하지 않는다. 예를 들어 중성 용액의 전체 이온 수를 0이라고 쓴 경우 ‘전하의 합과 입자 수를 혼동했을 가능성’과 ‘반응에 참여하지 않는 이온도 지웠을 가능성’을 구별한다. `총전하는 0인가?`, `Na⁺가 없어지는 반응식이 있는가?`를 순서대로 물어 필요한 설명으로 보낸다.

동일 핵심 기능에서 두 번의 독립 재확인 실패가 이어지면 같은 설명·같은 문제를 무한 반복하지 않는다. 계산 한 단계로 줄이기, 표를 채우는 대체 설명, 수식 없이 입자로 보기, 모르는 용어 선택, ‘어디부터 막혔는지’ 입력 중 오류에 맞는 길을 제시한다. 이후 휴식·다른 개념 탐색·현재 단계 보관을 허용한다. 핵심 진급은 미확인으로 남기되 뒤 본문 열람을 차단하지 않는다. 콘텐츠 오류 신고도 가능해야 한다.

## 4. 상호작용과 개념 노트

상호작용은 정답 표시 버튼을 누르는 장식이 아니어야 한다. 예측→조건 조작/자료 읽기→결과 확인→설명→새 조건 적용 중 어디에 쓰이는지 명시한다. 상태와 학생의 실제 입력을 저장하고, 새로고침·뒤로 이동 시 복구한다.

| 형식 | 구현할 학생 행동 | 유효한 평가 근거 | 구현 주의 |
|---|---|---|---|
| 수치·단위 입력 | 값과 단위를 분리 또는 식으로 입력 | 정답·단위·중간값 | 동치 분수·소수·표현 인정; 의미 없는 공백 차이로 오답 금지 |
| 입자/자료 조작 | 특정 이온끼리 짝짓기, 표 값 조절, 예측값 먼저 제출 | 바뀐 조건·고정 조건·최종 해석 | 드래그 대안으로 선택+이동 버튼과 표 입력 제공 |
| 순서 배열 | 반응 전 수→반응 쌍→잔여 수→총수→부피 나누기 | 순서와 필요 이유 | 가능한 복수 순서를 명세하고 한 고정 배열만 정답 처리하지 않음 |
| 그래프/도표 읽기 | 축·단위·범례 표시, 구간 지정, 수치 비교 | 선택 구간과 근거 | 색만으로 판정하지 않음; 같은 값을 자료표로 제공 |
| 그리기 | 화살표·입자·관계도를 학생이 그림 | 핵심 요소·방향·보존 관계 | 그림 실력·필체 미관 채점 금지; 구조화 입력 대안 제공 |
| 짧은 설명 | 왜 그런지, 무엇이 같은지/다른지 설명 | 개념·조건·인과 연결 | 키워드 개수만으로 정답 판정 금지 |
| 개념 노트 | 정의·조건·내 예·주의점·질문을 자기 말로 작성 | 수정 전후 내용과 근거 | AI의 완성 문장을 복사한 것을 독립 설명으로 세지 않음 |
| 선택형 | 공식 시험 형식·진단 선택 | 정답과 필요 시 근거 | 모든 활동을 5지선다로 바꾸지 않음 |

V1의 각 성취기준은 읽기 외에 최소한 **생성 응답(설명/계산/그리기) 한 종류와 개념에 맞는 자료/과정 활동 한 종류**를 갖춰야 한다. 조작이 부적합한 과학 윤리 등에서는 주장–근거–한계 구조화가 과정 활동이 된다. 형식 비율을 맞추기 위해 원래 서술형을 억지로 5지선다로 변경하지 않는다. 중화 대표 경로에서는 선택형 2개뿐 아니라 입자 짝짓기, 수치·표 작성, 과정 배열, 설명, 노트, 조건 반례가 실제로 작동해야 한다.

개념 노트 AI 검토는 학생이 ‘검토받기’를 눌렀을 때 해당 개념의 승인된 source block과 rubric만으로 실행한다. 출력은 `좋게 연결한 점`, `확인이 필요한 문장`, `근거 위치`, `구별 질문`, `수정 제안`으로 제한한다. 학생의 원문은 유지하고 스스로 고치게 한다. 서버 응답에는 `criterionId`, `quotedStudentText`, `basisBlockIds`, `verdict(supported|contradicted|unclear)`가 포함되어야 한다. 근거가 없으면 단정하지 않는다.

AI가 노트를 읽었다는 이유로 숙달이나 진급을 자동 승인하지 않는다. 수치·선택·구조화 관계는 결정적 채점으로 확인하고, 서술·그림의 의미가 불명확하면 검토 보류 및 동등한 구조화 확인 과제를 제공한다. AI 지연·오류·사용 한도 초과 시 노트 저장, 자기 점검표, 검수된 예시, 결정적 확인 과제는 계속 동작한다. AI 서비스 장애가 필수 진급의 유일한 길을 막아서는 안 된다.

## 5. 진급과 숙달 증거의 구별

`진도`(미시작/진행/회차완료), `핵심 이해 근거`(미측정/도움받아 해결/독립 적용 확인/지연 재확인/재확인 필요), `선택 심화`를 서로 다른 필드로 관리한다. 다음 버튼·스크롤·열람 시간·영상 시청·5회 연속 클릭은 이해 근거가 아니다. 정답 여부와 첫 시도 여부·힌트/해설 노출·동일 문항 경험을 함께 저장한다.

다음은 V1의 **조정 가능한 초기 운영 규칙**이다. 과학적으로 검증된 최적 점수선이나 학습효과 보장으로 쓰지 않는다.

1. 각 개념 gate에 핵심 `skillId`, 치명적 오개념 여부, 인증용 probe blueprint를 등록한다. 점수 평균만으로 빠진 기능을 덮지 않는다.
2. 핵심 진급은 **시작 전에 5개 과제를 사전 고정한 하나의 `gateSession`**으로 판정한다. 서로 다른 5개 과제의 최초 제출을 모두 받아 고정 분모 5로 계산하며, 오답도 분모에 포함한다. 정답이 나올 때까지 시도를 추가하거나 잘 맞힌 5개만 골라 계산하지 않는다. 통과 조건은 **5개 중 4개 이상 정답(80% 이상) + 최소 두 자료/과제 형식 + 적어도 한 개의 조건이 달라진 전이 문제 성공 + 모든 필수 skill의 도움 없는 성공 근거**를 모두 충족하는 것이다. 필수 관계의 오류가 해결되지 않았으면 4/5 이상이어도 통과시키지 않는다. 미제출 과제가 있으면 세션 미완료이며 임의로 분모를 줄이지 않는다.
3. 원문에서 같은 수치·상황을 설명한 뒤 그대로 묻는 문항은 학습 확인으로 남기되 독립 gate 증거에 자동 포함하지 않는다. 문항마다 `exposureGroupId`, `reasoningFamilyId`, `isWorkedExampleClone`를 둔다.
4. 같은 문항/동일 정답 구조를 연속 다시 맞힌 기록은 한 개의 독립 증거로도 중복 집계하지 않는다. 보기 순서·숫자만 바꾸고 추론이 동일한 것은 근접 연습이며 낯선 전이 성공과 구별한다.
5. 평가 세션 진행 중 정답·해설·핵심 힌트를 요청하면 해당 `gateSession` 전체를 `practice`로 전환하여 그 세션의 모든 시도를 진급 판정 증거에서 제외한다. 이미 맞힌 앞 문항만 떼어 다음 평가에 합산하지 않는다. 도움을 받은 답 수정은 `assisted` 연습 기록으로 남긴다. 다섯 과제 제출과 서버 판정이 끝난 뒤 여는 피드백은 완료된 당시의 독립 수행을 소급 취소하지 않는다. 화면을 닫거나 새 세션에 들어왔다고 문항의 노출 기록을 초기화하지 않는다.
6. 자작 유형의 인증 문항은 검수된 고정 은행 또는 정답·보존 관계가 결정적으로 검증된 제한된 template만 사용한다. 요청 시 AI가 무제한 생성한 문항을 곧바로 gate로 채택하지 않는다.
7. 충분한 새 probe가 없으면 `evidence_insufficient`로 표시하고 실제 제작 대상에 남긴다. 가짜 숙달을 부여하지 않으며 다른 학습 열람·활동은 허용한다.
8. 점수 미달이어도 학생은 현재 보충 경로, 다시 확인할 기능, 도움받아 해결한 기록을 볼 수 있다. ‘실패’, ‘과학 능력 부족’으로 낙인찍지 않는다.

재평가는 보충 후 **새로운 5개 과제를 사전 고정한 새 `gateSession`**에서 실시한다. 이전 세션의 맞은 문항이나 보충 후 교정 답을 합산하지 않고, 새 세션에서도 오답을 포함한 분모 5를 유지한다. 이전 노출·같은 예제 복제 여부를 서버에서 점검하여 인증용으로 적격인 새 과제만 배정한다. 충분한 새 과제가 없으면 `evidence_insufficient`이며 연습으로 계속할 수 있다. 두 차례 평가 실패 시 복구 경로를 안내하되, 평가 중 오답이 나왔다는 이유로 남은 과제를 몰래 바꾸지 않는다.

독립 적용 gate를 통과하면 다음 권장 개념의 진급 상태를 연다. **지연 숙달 확인까지 기다리느라 다음 학습을 며칠 잠그지 않는다.** 지연 확인은 별도 복습 큐에서 운영한다. 읽고 싶은 뒤 개념을 직접 열어 보는 탐색과 인증된 진급 상태도 분리한다.

복습 초기 정책:

- 오답 즉시: 구별 질문→보충→원래 답 수정. 교정 기록이며 독립 증거 0.
- 당일 새 조건 확인: 보충 뒤 서로 다른 활동 3개 또는 10분 이상 지난 때 제안할 수 있다. 둘은 운영상 간격일 뿐 기억 연구의 최적값으로 주장하지 않는다. 이것만으로 지연 숙달을 부여하지 않는다.
- 약 24시간 뒤: 원래 오답을 다시 풀거나 다른 수치의 근접 문제로 개념을 다시 꺼내 본다. 원문 재풀이 성공은 기억 유지의 보조 기록이다.
- 3~7일 뒤: 표↔입자/그래프 전환, 질문 역방향, 반례 조건 등 다른 `reasoningFamilyId` 전이 문항을 제공한다. 이전 해설 미노출·도움 없음 조건으로 확인한다.
- ‘나중에도 확인’은 시간 간격이 있는 두 회차의 독립 성공 중 하나가 전이 문제이고 핵심 기능이 다시 확인될 때 부여한다. 실제 간격·문항·노출 여부를 함께 보관한다.
- 약 21일 뒤 복습은 이미 배운 관계를 유지하기 위한 추가 점검이다. 21일은 초기 운영 일정이며 최적 간격이나 ‘나중에도 확인’ 등급의 필수 대기 기간이 아니다. 지연 등급은 바로 위의 독립 성공 두 회차·전이·핵심 기능 조건으로 판정하고, 21일 복습 참석 자체로 등급을 주지 않는다.
- 실패 시 이전의 성공 사실을 지우지 않고 현재 `needs_recheck`와 이유를 추가한다. 시험 일정·학생 부담에 따라 간격을 조정한다. 새 콘텐츠 버전의 과학적 수정으로 무효화된 문제는 학생 실패로 처리하지 않는다.

서버는 `gateSession`에 `gateSessionId, policyVersion, fixedItemInstances[5], requiredSkillIds, assignedAt, status, practiceReason, finalizedAt, scoreNumerator, scoreDenominator=5`를 저장한다. attempt에는 `gateSessionId, attemptId, idempotencyKey, itemId, itemVersion, instanceId, exposureGroupId, reasoningFamilyId, response, responseRevision, submittedAt, assistanceEvents, solutionExposedAt, scorerVersion, evidenceEligibility`를 저장한다. 같은 요청의 네트워크 재전송이나 더블 클릭은 한 번만 처리한다. 빠른 응답 시간만으로 부정행위를 확정하지 않고 필요하면 근거 재확인을 제안한다.

힌트·해설을 제공하는 서버 endpoint는 **노출 기록을 먼저 영구 저장하고**, 진행 중인 평가라면 세션을 `practice`로 바꾼 뒤 해당 내용을 응답한다. 노출 저장에 실패하면 해설 본문을 먼저 반환하지 않는다. 제출과 힌트 요청이 겹칠 때도 서버의 처리 순서와 세션 상태가 일관되게 적용되어야 한다. `evidenceEligibility`는 서버가 배정·노출 이력·도움 요청·세션 상태·문항 버전으로 계산한다. 클라이언트의 ‘힌트 안 봄’, ‘처음 풂’ 선언과 화면 이벤트는 보조 정보일 뿐 판정 권한을 갖지 않는다. 문항 정답·해설을 제출 전 payload나 숨긴 DOM으로 미리 내려보내지 않는다.

## 6. 선택 하이탑 심화 창

하이탑 자료는 2021년판/2015 교육과정 자료가 포함되어 있어 현행 필수 범위를 대체하지 않는다. 각 선택 묶음에 `현행 기준에서 더 깊게 보기`인지 `교육과정 밖 선택 확장`인지 표시한다. 교과서·하이탑 원문 문항을 그대로 문제은행에 넣지 않고, 조건·상황·자료 표현·질문을 검수된 변형 또는 독립 자작으로 구성한다. 원본 그림·재제작 프롬프트는 현재 사용자의 검토 방침과 도판 manifest 상태를 따른다.

선택 심화는 현재 단계 위의 접근 가능한 drawer/modal 또는 작은 별도 경로로 제공한다. 닫으면 원래 문제 초안으로 복귀한다. 스크롤 끝에 도달했다는 이유로 선택 심화를 완료 처리하지 않는다. **설명을 읽은 뒤 연계 형성평가 최소 2개(직접 적용 1+조건 변경/반례 1)를 제공하고 이를 확인해야 해당 선택 묶음의 완료가 된다.** 당장 닫거나 중단할 수 있으며 상태는 ‘읽음·확인 남음’으로 남는다. 선택 심화 미완료·오답이 핵심 과정의 진급을 막지 않는다. 옵션 통과를 기본 개념 확인의 대체 점수로 합산하지 않는다.

**필수 내용을 선택 창으로 옮기지 않는다.** ‘전체 이온 수와 단위부피당 이온 수의 구별’은 N14, ‘중화량·전체 용액량과 최고 온도 비교 조건’은 N17을 포함한 핵심 본문에서 충분히 설명하고 평가해야 한다. 이 내용의 정의·조건·추론·예시·반례를 모두 기본 경로에 유지한다. 선택 창을 열어야만 핵심 평가의 근거를 배울 수 있는 구조는 금지한다.

중화의 선택 하이탑 확장은 **이미 배운 원리를 추가 상황과 자료에 적용하는 새 고난도 활동**이다. 예를 들어 핵심 경로와 다른 추가 실험 자료에서 일부 가려진 값을 여러 단서로 역산하거나, 제시된 실험 계획 가운데 비교 조건이 충족되는 것을 고르고 판단을 유보해야 하는 경우를 설명하게 할 수 있다. 기존 필수 설명과 평가를 유지한 상태에서 추가 연습을 제공하며, 선택 자료만의 새 정보가 필요하면 그 활동 안에서 모두 제공한다. 이 활동을 하지 않았다는 이유로 기본 과정의 학습 근거가 빠지거나 핵심 진급이 불가능해져서는 안 된다. pH 로그·산화수·엔탈피 계산을 몰래 핵심 gate에 섞지 않는다. 선택 형성평가 은행이 준비되지 않았으면 해당 확장 콘텐츠를 완료 가능한 학습 상품으로 게시하지 않는다.

## 7. 영상 미등록 상태까지 실제 작동하게 만들기

각 영상 자리는 실제 역할을 가진 `VideoPlan`으로 작성한다. `videoId, conceptId, sourceBlockIds, goal, targetDifficulty, storyboard[], transcriptDraft, pauseQuestions[], returnStepId, fallbackBlockIds, productionStatus, assetUrl, captionsUrl`을 둔다. 영상 설명 한 줄과 빈 플레이어만 만들지 않는다.

`productionStatus=planned`이면 깨진 재생 버튼·0:00 플레이어를 숨기고 ‘영상 준비 중 · 글과 그림으로 이어서 학습할 수 있어요’와 해당 대체 단계로 연결한다. 영상의 계획은 데이터에서 확인 가능해야 하며 실제 등록된 경우에만 재생을 표시한다. 모든 필수 설명·평가는 텍스트/도판 경로로 가능해야 한다. 영상 미등록·재생 장애·시청 건너뛰기가 진급을 막지 않는다. 영상 시청 자체는 점수나 숙달 증거로 쓰지 않는다.

## 8. 모의고사 풀이, 해부, 전략 갱신

실전은 전략 학습, 여러 개념 혼합, 시간 제한 시험으로 구분한다. 시험 중에는 원문·초안·응답만 제공하고 해설은 제출 후 연다. 전략 학습에서는 힌트를 사용할 수 있지만 도움 사용을 기록한다. 평가원·교육청·자작 문제의 표시를 항상 구별한다.

평가원 2025 원문은 한 PDF 페이지에 여러 문항이 배치되어 있다. 문항별 원문 표시에는 해당 문항 전체의 지문·그림·표·선지를 담은 검수된 crop 좌표를 사용하거나 원문 페이지를 확대해 제공한다. crop은 문항 내용을 바꾸지 않는다. 페이지 전체를 보여 주면 함께 노출된 다른 문항 ID도 노출 장부에 기록한다. 같은 페이지를 이미 본 다른 문항을 ‘처음 보는 문제’로 잘못 인증하지 않는다. 접근성용 텍스트·자료표는 원본과 대조한 병렬 표현이며 원문 자체를 조용히 교체하지 않는다.

각 `ExamAnalysis`의 학생용 완료 조건:

1. `왜 묻는가`: 공식 출제의도가 확인되면 출처와 인용 범위를 붙이고, 자체 분석은 그대로 자체 분석이라고 표시한다. 2025 평가원 상세 공식 의도는 대표 8문항에 제공되었다는 기록을 지킨다.
2. `자료 신호`: 축·단위·범례·같다고 준 조건·수치의 의미·조건문·최종 질문을 구체적으로 짚는다.
3. `첫 접근`: 가장 정보가 많은 자료와 그 이유를 설명하고, 대안 접근이 있으면 인정한다.
4. `단계 추론`: 중간값·보존 관계·판정에 사용한 조건을 빠뜨리지 않는다.
5. `선지 판정`: 모든 보기와 ①~⑤를 각각 판정한다. 오답은 어떤 조건에서 왜 틀리는지 설명한다.
6. `오답 구별`: 원인 후보→짧은 구별 질문→복습 block→다른 문항으로 돌아오는 경로.
7. `전략과 한계`: 적용 단서, 전제, 풀이 순서, 반례를 학생이 확인한다.
8. `유사·전이 연습`: 같은 핵심 관계의 직접 적용, 다른 자료 표현, 조건이 달라져 기존 요령이 깨지는 반례를 포함해 **최소 3개의 연계 과제**를 제공한다. 다른 분석과 검수된 과제를 공유할 수 있으나 이미 본 문항은 독립 전이 확인으로 재집계하지 않는다. 은행이 없으면 완료로 위장하지 않는다.

자료에서 특정 유형이 많이 보인다는 사실은 현재 수집 집단에서 관찰된 빈도다. 고1 3월 중학 45, 고교 학평 200, 평가원 예시37을 분리하고 학년·월·시험 범위를 조건으로 비교한다. 성취기준 연결 횟수를 실제 수능 비중·난도·적중 확률로 바꾸지 않는다. 미출제 개념도 교재에서 삭제하지 않는다.

전략 객체는 `strategyId, version, applicableConditions, dataSignals, steps, counterexamples, sourceItemIds, validationItemIds, limits, changeReason, supersedesVersion, effectiveAt, reviewStatus`를 가진다. 새 회차 수집은 원문·정답 검증→문항별 분석→기존 전략에 맞는지/반례인지 분류→기존·새 대표 문항과 보류 검증 문항으로 대조→검토 승인→버전 공개 순서다. 새 한 문항만으로 전체 전략을 자동 교체하지 않는다. 학생 기록은 당시 전략 버전을 유지하고, 의미가 바뀐 전략에만 ‘새 조건이 추가되었어요’라는 복습을 연결한다.

발행 주체별 원문 취급 데이터는 반드시 분리한다:

| 발행 주체/자료 | 원문·변형 정책 | V1 처리 |
|---|---|---|
| 한국교육과정평가원 공식 예시/향후 공식 문제 | 사용자 요청에 따라 원문 지문·조건·그림·선지·배점·공식 정답을 보존. 변형이 필요하면 별도 자작 문항 ID | 원문과 자체 해설을 별도 레이어로 제공. 원문 오류/주의는 밖에 주석으로 남김 |
| 서울·부산·인천·경기 등 교육청 전국연합학력평가 | 평가원 원문 지시를 교육청으로 자동 확대하지 않음 | `publisher`, `organizer`, `distributionSource=EBS`, `sourcePolicy`, `releaseStatus` 별도 기록. 확보한 원문은 분석 근거로 보존; 학생 공개 방식은 해당 발행 주체에 적용되는 확인 상태 사용 |

이는 자료 흐름 명세이며 상업 이용 허락을 법적으로 판정한 결과가 아니다. 원문을 확보한 사실과 앱 공개 상태를 동일한 Boolean으로 합치지 않는다. 현재 학생용 준비가 안 된 교육청 문항은 자료 목록에 기록하되 오답 진급용 문제로 자동 노출하지 않는다. 준비 상태가 승인되면 같은 학생 실전 엔진에 들어오도록 구현하여 37문항만 가능한 폐쇄 구조를 피한다.

### 중화 조작 엔진의 입력·출력 계약

수량의 단위는 양의 일정량 N개로 정규화한다. 아래 `2`는 2N개/mL이며 원자 한 개를 뜻하는 N과 혼동하지 않도록 범례를 표시한다. 실제 용액의 모든 화학평형을 계산하는 시뮬레이터가 아니라, 교재의 명시된 단순 입자 모형이다.

```json
{
  "activityId": "NEU-MIX-01",
  "modelVersion": "neutralization-monovalent-1.0",
  "solutes": [
    {"id":"HCl", "positive":"H+", "negative":"Cl-", "perMlInN":2, "volumeMl":15},
    {"id":"NaOH", "positive":"Na+", "negative":"OH-", "perMlInN":3, "volumeMl":10}
  ],
  "assumptions": {
    "completeDissociation":true, "reactionRatioHtoOH":"1:1",
    "allIonsMonovalent":true, "otherReactions":false,
    "waterSelfIonizationOmitted":true, "volumesAdd":true
  },
  "interaction": {
    "predictBeforeReveal":true,
    "editable":["volumeMl"],
    "lockedDuringAttempt":["perMlInN","assumptions"],
    "responseFields":["initialH","initialOH","reactedPairs","remainingH","remainingOH","remainingNa","remainingCl","totalIons","totalVolume","ionsPerMl","acidity"]
  },
  "expected": {
    "initialH":30,"initialOH":30,"reactedPairs":30,
    "remainingH":0,"remainingOH":0,"remainingNa":30,"remainingCl":30,
    "newWater":30,"totalIons":60,"totalVolume":25,"ionsPerMl":2.4,"acidity":"neutral"
  }
}
```

계산식은 `a=cH*VH`, `b=cNa*VNa+cK*VK`, `pairs=min(a,b)`, `H=max(a-b,0)`, `OH=max(b-a,0)`, `Cl=a`, `Na=cNa*VNa`, `K=cK*VK`, `total=H+OH+Cl+Na+K`, `totalVolume=VH+VNa+VK`, `density=total/totalVolume`이다. UI 설명은 한국어로 제공한다. 입력이 음수가 아닌 유한값이고 총부피가 양수인지 검증하며, 총부피가 0일 때는 농도와 액성을 계산하지 않는다.

구현에서는 위 식을 한국어 변수 설명과 함께 사용한다. 조작 범위는 검수된 값으로 제한하고 숫자 비교는 유리수 또는 명시한 허용 오차로 처리한다. 전하 보존 `H+Na+K=OH+Cl`, 반응 전후 원소 수 보존, 반응 후 H와OH가 동시에 양수이지 않음을 검증한다. 물 분자는 총이온 수에 더하지 않는다. 열량/온도 활동은 추가로 같은 산·염기, 초기 온도, 밀도·비열, 손실·용기·희석열 조건을 받아야 한다. 열량의 상대 지표는 pairs, 온도 상승의 상대 지표는 pairs/totalVolume이다. 계수를 주지 않고 이를 °C로 출력하지 않는다.

### 숙달 판정 실행 예

학생 A는 N15에서 C1·C2·C3를 이미 풀었다. 따라서 이를 독립 평가에 재사용하지 않는다. 평가 세션 G1에는 별도로 제작·검수한 **G1-Q1·G1-Q2·G1-Q3·G1-Q4·G1-Q5의 정확히 5개 새 과제**를 사전 고정한다. 이들은 기존 C문항이나 N-X문항의 ID만 바꾼 복제물이 아니며, 학생에게 미노출인 새 평가용 추론 가족에서 자료·질문 관계를 검수한 과제여야 한다. 아직 해당 과제를 제작하지 않았다면 예시 ID를 완성된 문제처럼 등록하지 않고 `evidence_insufficient`로 남긴다.

G1-Q1·G1-Q2를 맞히고 G1-Q3에서 ‘중성이라 이온0’이라고 답했다면 그 시점은 2정답·1오답·2미제출인 진행 상태다. 오답 G1-Q3를 빼거나 새 probe를 여섯 번째로 추가하지 않는다. 학생이 다섯 과제 제출 전에 G1-Q3 해설을 요청하면 서버가 노출을 먼저 저장하고 G1 전체를 연습으로 전환한다. 이후 G1-Q3를 구경꾼 이온을 포함한 답으로 고치고 G1-Q4·G1-Q5를 맞혀도 G1은 진급 증거가 되지 않는다. G1-Q3를 10번 다시 맞힌 기록도 연습이다.

N03/N10 보충 후에는 해당 학생에게 미노출인 적격 과제 R1·R2·R3·R4·R5를 고정한 새 평가 세션 G2를 시작한다. G1의 두 정답이나 도움받은 교정을 G2에 합산하지 않는다. G2에서 5개 모두를 도움 없이 제출하여 4/5 이상이고, 두 형식·조건 변경 전이의 성공·모든 필수 skill 성공 및 미해결 핵심 오류 없음 조건을 함께 만족하면 진급한다. 예를 들어 5/5이며 모든 추가 조건을 만족하면 통과다. 4/5여도 필수 `spectator_ions_remain` 오류가 남으면 미통과다. 이 기록만으로 ‘오래 기억함’은 표시하지 않는다.

다음 날 원래 틀린 G1-Q3를 맞히면 지연 원문 재확인이다. 3~7일 뒤 다른 검수된 자료 표현에서 구경꾼 이온·전하·부피당 수를 도움 없이 설명해야 전이 근거가 추가된다. 지연 등급은 앞서 정한 서로 시간 간격이 있는 독립 성공 두 회차와 전이·핵심 기능 조건으로 결정한다. 약21일 뒤의 추가 유지 점검은 이 등급의 필수 대기 조건이 아니다. 그 사이 선택 하이탑 창의 형성평가를 틀렸다면 선택 확장만 미완료다. AI 노트 검토 서버가 실패해도 결정적 확인 과제와 핵심 진급은 작동한다.

중화 단원 전체 이해에는 개념 gate 외에 심화의 열/온도 구별, 역추론, 수능 전략의 조건 검토가 따로 필요하다. 앞의 핵심 gate 통과를 단원 전체 완전 숙달로 확대하지 않는다. N19~N28의 수행과 지연 재확인을 각각의 skill에 기록한다.

# 단계별 개발 프롬프트와 완료 검사

이 문서는 Claude의 긴 개발 작업을 이어 갈 때 사용한다. 00의 전체 지시가 항상 우선한다. 매 단계가 끝날 때 `진행기록.md`에 실제 완료·검증·잔여 작업·다음 파일을 기록한다. 새로운 대화에서 ‘이 파일과 진행기록을 읽고 다음 미완료 단계부터 계속하라’고 지시할 수 있다. 아래 단계마다 사용자 허락을 다시 받아야 한다는 뜻은 아니다.

## 1단계: 자료 보존과 개발 기반

**전달 프롬프트**

> 첨부 교재를 원본으로 학생용 V1 프로젝트를 시작하라. 먼저 파일 manifest, 고유 성취기준·학습 묶음·문항·도판·출처·선수개념의 관계를 만들고 원문 보존 검사를 구현하라. 화면을 먼저 임의 내용으로 채우지 말라. React/TypeScript/Vite와 Firebase Emulator, Cloudflare Workers Static Assets의 개발 구조를 만들고 환경별 설정 예제와 비밀값 목록을 구별하라. 콘텐츠 스키마·문항 비공개 정답·학생 기록 스키마를 분리하라.

**검사**

- 교재31고유 성취기준·32묶음·291자작/재구성·37평가원 문항이 모두 등록된다.
- 수집색인의 교육청245·평가원37과 교재를 중복 제거해573개 출발 ID를 확인한다. 이중 교육청245의 학생 해설 상태는 준비중으로 구별한다.
- 원문 문단·목록·표 셀·수식·이미지·그림 읽기·문항·정답의 블록이 어디로 갔는지 모두 추적한다. 제작 프롬프트·출처 메모의 메타데이터 이동도 기록한다.
- 출처가 빠진 그림, 정답 없는 문제, 가르치지 않은 필수 개념에 의존하는 문제, 깨진 이미지 경로를 오류로 반환한다.
- 현재 실행 가능한 개발 환경과 단순 예제 환경을 명확히 구별한다. `.env.example`에 실비밀값이 없어야 한다.

## 2단계: 디자인과 대표 단원 전체 경로

**전달 프롬프트**

> Mintlify Light를 바탕으로03의 한글·넓은 화면 기준을 적용하라. 중화 단원 N01~N30 전체를 선수 진단부터 지연 복습까지 구현하라. 개념 설명을 축약하지 말고 교재 문단에 연결하라. 입자 조작·표 입력·근거 설명·노트·형성평가·평가원 분석이 하나의 학생 경로로 작동해야 한다. 비어 있는 영상 슬롯과 선택 심화는 각각의 올바른 상태를 보이게 하라.

**검사**

- 실제 원고와9개 기존 문항이 모두 보존되고 각 활동의 과학 계산이 검산된다.
- 첫 예측→조작 결과→설명→수정 답안이 저장되며 뒤 피드백이 해당 입력을 참조한다.
- 1440/1920 화면은 넓게 사용되고 1024가로 태블릿에서도 주요 행동이 숨지 않는다. 본문은 지나치게 긴 한 줄이 되지 않는다.
- 미제작 영상·미연결 AI·네트워크 장애를 실제로 재현해 학생 답안이 보존되는지 확인한다.
- 대표 경로가 통과해도 전체 앱 완료라고 보고하지 않는다.

## 3단계: 계정과 학습 기록

**전달 프롬프트**

> 02명세대로 다섯 가지 가입과 계정 연결, 학생 기록 저장, 자동 저장 충돌 처리, 서버 채점·통과·복습을 구현하라. 네이버는 검증된 custom auth를 사용하라. uid를 계정·학습의 기준으로 유지하고 연락 이메일과 인증 증거를 구별하라. 실제 설정이 없는 provider는 성공한 척하지 말고 필요한 설정을 구체적으로 보고하라.

**검사**

- 학생A가 학생B의 노트·시도·이용권을 읽거나 쓰는 Rules 시험이 거부된다.
- 클라이언트가 정답·점수·통과·다음 복습일·이용권을 조작할 수 없다.
- 같은 제출의 중복 전송으로 두 번 채점하거나 진도를 중복 갱신하지 않는다.
- 평가5개 묶음이 서버에서 미리 고정되고 오답을 분모에서 제거하지 않는다. 힌트·해설 노출 기록을 서버가 판단한다.
- 새로고침·재로그인·다른 기기에서 위치·작성물·시도·노트가 복구된다. 오프라인/충돌은 학생 선택 없이 덮어쓰지 않는다.
- 이메일 인증·비밀번호 재설정·Apple 비공개 이메일·Microsoft 학교 계정 제한·네이버 연결 충돌을 포함한다.
- 계정 연결 전후 같은 UID·학습 이력 보존을 확인한다. 단순 이메일 일치만으로 합치지 않는다.

## 4단계: 전체 교재와 인터랙션 확장

**전달 프롬프트**

> 검증한 대표 구조를 나머지 학습 묶음에 적용하라. 모든 문단과 도판을 보존하며 개념 특성에 맞는 활동을 선택하라. 용어마다 같은 템플릿을 복제하지 말고 측정·그래프·입자·분류·인과·근거 설명 등 해당 개념을 확인할 방법을 구현하라. 필수 심화와 선택 하이탑 확장을 구별하라.

**검사**

- 32묶음 모두 일곱 단계의 연결과 해당 선수 보충을 갖춘다.
- 각 묶음에 선택형 외의 의미 있는 산출물과 과정 활동이 적어도 각각 한 종류 있다.
- 필수 평가를 풀기 위한 정의·조건·예제·그림 읽기가 선행 단계에 있다.
- 감염병 검사·스마트 온실은 `05_보완주제_활동과영상설계.md`의 표적/도구/신호 분류, 증폭 수량 모형, 정보/물/전기 경로, 측정→제어→재측정 활동과 영상 슬롯을 구현한다. 가상 수치를 실제 진료·농업 기준으로 표시하지 않는다.
- 현재 도판43개의 출처·재제작 캡션, 기존 생성3개·이번 자체도해3종의 출처 상태가 정확하다. 실제 manifest와 수가 다르면 원인을 확인한다.
- 선택 심화를 읽었어도 관련 평가 없이 이수로 표시하지 않는다. 선택 심화가 기본 진도를 무한히 가두지 않는다.
- 독립 검수된 새 문항 은행이 없으면 무작위 생성 문제로 통과 시험을 대신하지 않는다. 필요한 제작 수량과 상태를 보고하고 해당 경로의 정식 배포를 막는다.

## 5단계: 모의고사 분석과 유사문항

**전달 프롬프트**

> 교육청245개와 평가원37개를 발행 주체와 교육과정으로 정확히 구별하라. 교재에 이미 있는 평가원37개는 중복 생성하지 말라. 각 문항을 학생이 먼저 풀고 모든 선지·조건·전략·오답 경로를 분석하도록 만들라. 미완성 교육청 해설을 보완하고 대표 문항마다 최소3종의 독립 유사문항을 집필·검수하라. 자동 생성 결과를 검증 없이 실전 문제로 발행하지 말라.

**검사**

- 기본 자료573개 ID와 새로 추가된 유사문항을 별도 집계한다. ‘현재 모든 유사문항 완성’이라는 잘못된 초기값을 두지 않는다.
- 각 문항의 원문 PDF쪽수·정답·자체 해설·선수개념·전략 버전·유사문항이 연결된다.
- 고1 3월45문항을 중학교 진단 범주로 유지한다. 실제2028수능 기출이라고 표시하지 않는다.
- 유사문항은 정답의 유일성, 단위, 표현, 그래프, 보기, 계산, 학습 근거를 검수한다.
- 실전 중 정답이 HTML/번들/alt/로그로 새지 않고 제출 뒤에만 분석을 제공한다.
- 새 시험을 추가하거나 오류 해설을 수정해도 과거 답안·콘텐츠 버전·전략 버전이 보존된다.

## 6단계: 배포와 인계

**전달 프롬프트**

> GitHub 소스에서 Cloudflare Workers Static Assets로 빌드·배포하는 경로를 완성하라. Firebase 서버 함수·Rules·인덱스는 별도 배포 대상으로 관리하라. 운영과 시험 환경을 분리하고 provider callback·허용 도메인·CORS·보안 헤더·SPA 새로고침을 검증하라. 결제는 연결하지 말고 이용권 인터페이스만 준비하라. 전체 자료·기능·검증의 완료 보고와 남은 외부 설정을 작성하라.

**검사**

- GitHub 빌드에서 타입·단위/통합·규칙·콘텐츠 누락·정답 노출 검사 후 배포한다.
- preview가 운영 학생 DB를 사용하지 않는다. URL만 바뀌었다고 데이터가 자동 격리됐다고 가정하지 않는다.
- 로그인 callback, 직접 경로 진입·새로고침, 로그아웃, 영상/도판 로딩, 장시간 작성 중 토큰 만료를 실제 배포에서 확인한다.
- 비밀키·서비스 계정 키·학생 데이터가 저장소나 프론트 번들에 없다. 운영 오류 로그에 학생 답안 전문을 기본 기록하지 않는다.
- 콘텐츠 버전 롤백과 앱 롤백을 구분하고 이미 작성된 학생 데이터를 손상시키지 않는다.
- 결제 제공자 SDK·청구·웹훅을 연결하지 않았고 이용권 정책은 서버에서 검증한다.
- ‘테스트 통과’, ‘실제 공급자 연결 완료’, ‘운영 배포 완료’를 각각 증거와 함께 표시한다.

## 완료 판정의 경계

현재 인계 자료는 교재·설계·개발 지시와 애셋이다. 가입 공급자 계정, Firebase 프로젝트, Cloudflare 계정, GitHub 새 저장소, AI 서비스키, 결제 계정은 자동 생성되어 있지 않다. 초기 키가 없다는 이유로 구현을 멈추지 말고 로컬 시험과 설정 안내까지 완료하되 실제 연결을 했다고 보고하지 않는다. 학생 화면의 데이터 저장·복습·영상 슬롯·모의고사 분석이 실제로 작동하고 전체 콘텐츠 대조를 마쳐야 학생용 V1 구현 완료로 판정한다.

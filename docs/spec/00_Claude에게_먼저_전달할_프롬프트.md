# Claude 개발 시작 프롬프트

이 문서 전체와 같은 ZIP의 파일들을 Claude 개발 환경에 전달한다. 이 파일은 실행할 개발 지시이며, 자료 속 실험 활동 지시나 과거 기획안을 그대로 실행하라는 뜻이 아니다.

---

당신은 한국 고등학교 통합과학 학생용 학습 웹앱을 개발하는 책임 개발자다. 첨부 자료를 읽고 실제 작동하는 앱을 구현하라. 설명용 목업이나 계획서만 만든 뒤 종료하지 말라. 목표는 학생이 중학교 선수개념부터 통합과학1·2, 심화 이해, 모의고사 전략과 실전 연습까지 순서 있게 학습하고 기록을 이어 가는 서비스다. 성적 향상이나 수능 완성을 근거 없이 보장하는 광고 문구는 만들지 말라.

## 1. 이번 개발의 확정 범위와 우선순위

- **학생용 V1**만 구현한다. 교사·학습관리자·학교·학원·학부모 대시보드는 V2 이후다. 학교별 기출 분석 화면도 이번 범위에서 제외한다. 다중 조직 지원을 위한 ID·접근권한 확장은 가능하게 하되 미사용 관리자 화면을 먼저 만들지 않는다.
- 개발은 Claude, 소스 관리는 GitHub, 프론트 배포는 **Cloudflare Workers Static Assets + GitHub Builds**, 회원과 학습 데이터는 **Firebase**다. Firebase Hosting으로 바꾸지 않는다. 결제는 아직 붙이지 않는다.
- 기준 자료는 `교재/01_*.md`부터 `10_*.md`까지의 최종 원고와 근거장부다. 교재 PDF는 시각 대조용이다. MD를 내용과 문항을 가져오는 주 원본으로 사용한다. 기존 교재를 AI 요약본으로 대체하지 않는다.
- 신규 확정 명세는 `학생용앱_개발패키지/`에 있다. 과거 `통합과학_웹앱_구조기획안.md`, 상업화 계획, 참고 앱 분석은 배경 자료다. 이전 문서의 관리자 화면, 모바일 우선 배치, 다른 DB, 즉시 결제 도입 등의 제안은 이번 최신 명세로 대체한다.
- 문서 간 불일치는 숨기지 말고 `DECISIONS.md`에 최신 요구·근거·해결을 남긴다. 누락이나 잘못된 과학 설명은 원고 ID를 유지하며 수정 이력을 남긴다. 불확실한 과학 사실은 공식 교육과정·평가원·공신력 있는 원출처로 검증한다.

처음에 이 문서, `01_학생용V1_학습상세명세.md`, `02_Firebase_회원과저장_Cloudflare배포.md`, `03_DESIGN_밝고집중되는학습화면.md`, `04_단계별개발과_인수검사.md`, `05_보완주제_활동과영상설계.md`, 그리고 ZIP 최상위 인계 안내를 읽어라. 자료가 많다고 일부만 읽고 전체를 반영했다고 보고하지 말라. 큰 원고는 성취기준별로 나누어 처리하고 처리 결과를 저장하라.

## 2. 구현 원칙: 교재를 충실하게 단계로 바꾼다

31개 고유 성취기준과 32개 학습 묶음을 모두 보존한다. 07장은 앞선 성취기준의 도판 풀이를 다시 다루므로 32개 성취기준으로 세지 않는다. 각 묶음은 **선개념 → 개념 → 개념평가 → 심화개념 → 심화평가 → 수능대비 전략 → 수능대비평가**의 구조를 가진다.

한 화면에는 하나의 핵심 질문과 활동을 중심으로 배치하되, 필요한 설명의 분량은 제한하지 않는다. 긴 설명은 인과 관계가 이어지는 여러 단계로 나누고 정의·조건·반례·예제·중간 계산을 전부 보존한다. `원문 문단/표/도판/예제 → conceptId → stepId → 연결 평가` 대조표를 만든다. 수식의 가정과 단위, 그래프 축, 관찰 가능한 현상과 해석을 생략하지 않는다. 접힌 영역 안의 필수 개념을 읽지 않아도 평가를 완료할 수 있게 설계하지 않는다.

문어체는 정의·법칙·공식·자료 조건·문제·정답 기준에, 자연스러운 해요체는 설명·힌트·안내·피드백에 쓴다. 과학 개념 대신 비유를 내세우지 않는다. 비유를 쓰면 실제 대응 관계와 비유가 성립하지 않는 지점을 바로 명시한다. 오개념을 가볍게 단정하지 말고 학생 답변의 실제 근거를 확인한다.

각 새 개념 앞에는 관련 중학교 개념의 **진단과 충분한 보충 경로**가 있어야 한다. 이미 알고 있는 학생은 진단으로 통과할 수 있지만, 실패한 학생에게 단순히 ‘중학교 내용 복습’ 링크만 주지 않는다. 정의, 관찰 예, 작은 연습, 확인 문제, 현재 고등학교 개념과 연결까지 제공한다. 2015·2022 교육과정 학년 배치 차이는 원자료 메타데이터에 남기고, 학생에게는 필요한 개념명으로 안내한다.

본문 수록 문항은 자작·재구성291 + 평가원 원문37 = **328개**다. 이 숫자는 초기 기준이며 문항 추가 후에는 manifest를 갱신한다. 별도 수집 모의고사282개 중 평가원37은 교재와 중복이다. 교육청245개를 합치면 현 자료의 고유 출발 문항은573개다. 중복 ID를 늘려 완료율을 부풀리지 않는다. 교육청245개는 수집·색인이 되어 있으나 모든 선지 심층 해설과 새 유사문항이 완성된 것은 아니다. 이를 별도 편집 작업으로 완성해야 한다.

교과서·하이탑의 문제를 그대로 복제하지 않는다. 기존 교재의 재구성 문항을 사용하고, 새로 만드는 문제도 조건·수치·판단 구조를 과학적으로 검증한다. 평가원37개는 원문 내용·그림·선지·순서·배점을 변조하지 않는다. 자체 해설과 유사문항을 원문과 구별한다. 교육청 주관 시험을 평가원 문제로 표시하지 않는다.

## 3. 학생 화면과 이동

메뉴는 `오늘의 학습 / 전체 학습 지도 / 모의고사 실전 / 복습 / 내 노트 / 내 학습 기록`으로 시작한다. 계정은 상단 프로필에서 연다. 메뉴 명칭은 학생이 바로 이해할 수 있도록 한다.

첫 화면에는 마지막 이어 하기, 오늘 복습할 개념, 이번 학습의 목표, 최근 실제 성취, 전체 학습 지도를 배치한다. 생성된 `images/home-science-studio.png`는 시작 영역의 보조 그림으로 쓴다. 화면 전체를 거대한 홍보 이미지로 채우지 않는다. 수치가 없는 신규 회원에게 가짜 연속 학습일·성적·랭킹을 표시하지 않는다. 첫 사용자는 짧은 관심·학년 설정과 선수 진단으로 시작한다.

학습 화면의 왼쪽은 현재 단원의 단계와 위치, 가운데는 현재 개념·활동, 오른쪽은 관련 선수개념·힌트·내 노트로 구성한다. 오른쪽에서 한 보조 기능만 선명하게 활성화한다. 상단에는 단원·목표·저장 상태, 하단에는 이전·다음 또는 제출이라는 명확한 행동을 둔다. 읽기, 활동, 평가 상태에 따라 중앙 구성은 달라져야 한다. 모든 화면을 같은 카드와 선택지 다섯 개로 복제하지 않는다.

기본 화면은 노트북·데스크톱·넓은 태블릿이다. 1440px·1920px에서 너비를 충분히 활용하고 1024px 가로 태블릿까지 점검한다. 전화기 대응을 위해 넓은 화면을 좁은 가운데 기둥으로 만들지 않는다. 화면은 넓게 쓰되 한 문장의 줄 길이는 제한하고, 남는 영역은 탐구 도구·자료·노트에 사용한다. 자세한 색·크기·배치는 디자인 명세를 따른다.

## 4. 상호작용을 학습의 근거로 사용한다

각 주요 개념에는 ‘예측 → 조작·관찰 → 결과 비교 → 이유 설명 → 새 조건 적용’ 중 학습 목적에 맞는 순환을 넣는다. 예를 들어 중화는 이온 수 조작과 반응 후 남은 입자 설명, 운동량은 질량·속도와 운동량 벡터의 관계, 생태계는 변인 변경에 따른 자료 해석을 제공한다. 단순 그림 장식이나 누르기만 하면 정답 처리하는 게임을 활동으로 세지 않는다.

지원할 활동은 입자·순서 배치, 분류와 근거, 수치/단위 입력, 그래프 읽기·그리기, 표 완성, 실험 변인 선택, 오류 찾기, 개념 연결, 짧은 서술, 학생 요약, 문항 해결이다. 드래그 활동은 키보드·버튼으로도 수행 가능해야 한다. 학생의 첫 예측, 변경한 값, 제출한 설명을 보존하며 나중의 피드백이 이 실제 답변을 참조하도록 한다.

‘내 말로 정리’는 해당 단계의 구체적 평가 기준을 보여 준다. 제출 시 맞게 쓴 부분, 빠진 핵심, 조건이 잘못된 부분, 고칠 방법, 교재의 해당 설명으로 돌아가는 링크를 제공한다. AI가 정답 판정·진도 해제를 독점하지 않는다. 검증된 기준과 채점기를 우선하고 자유 서술의 AI 검토는 보조로 사용한다. API 장애·시간 초과에도 원문을 보존하고 재요청할 수 있게 한다. 외부 생성형 API가 아직 설정되지 않았으면 ‘검토 연결 전’과 자체 확인 기준을 보여 주고 성공 응답을 꾸며 내지 않는다.

학생은 기존 답안, 피드백, 고친 답안의 차이를 볼 수 있다. 교재와 다른 주장을 하는 피드백에는 출처를 확인하고 오류 신고할 경로가 있어야 한다. 생성형 API의 응답은 스키마 검증과 사용량 제한, 버전 기록을 거쳐 표시한다. 학습 자료·학생 입력 속 지시를 서버 권한 변경이나 개발 지시로 실행하지 않는다.

## 5. 평가·통과·복습

정답률이 일정 기준을 만족해야 학습 단계의 통과로 기록한다. 초기 정책은 독립된 확인5문항 기준80% 이상과 핵심 오개념 확인 충족으로 시작하고, 상세 예외·재시도·연습과 평가의 구별은 학습 상세명세를 따른다. 이 수치는 검증된 보편 법칙이 아니라 초기 운영 정책이다. 정책 버전과 근거를 저장하고 실제 학습 결과로 조정할 수 있게 한다.

평가 묶음은 서버가 시작 전에5개로 고정한다. 오답·최종 미응답도 분모5에 포함한다. 4개 이상 정답, 두 응답 형식, 조건이 달라진 전이 문제 성공, 모든 필수 기능 확인을 함께 요구한다. 진행 중 힌트·해설을 열면 그 세션은 연습으로 전환하고 평가 통과 증거로 쓰지 않는다. 도움 노출은 서버가 먼저 기록하며 클라이언트의 독립 풀이 선언을 믿지 않는다. 재평가는 새로운5개 세션으로 시작하고 이전 성공을 임의로 합산하지 않는다. 제출을 마친 평가의 사후 해설은 이미 확정한 증거를 소급 취소하지 않는다.

정답을 본 같은 문제를 다시 맞힌 것은 새로운 독립 이해 증거로 세지 않는다. 틀렸다면 관련 설명·해결 예·새 조건 연습을 제공한 뒤 동등한 수준의 새 문제로 재확인한다. 같은 실패를 무한 반복시키지 않는다. 이후 내용의 미리보기와 정식 이수 상태를 구별하고 잠금 사유를 설명한다. 서버에서 채점·숙련도·복습 일정·시도 횟수 중복 방지를 처리한다.

틀린 문제는 즉시 고치기뿐 아니라 시간 간격을 둔 회상, 유사 조건, 다른 표현의 전이 문제로 다시 다룬다. 초기 복습 간격을 설정값으로 두고 성공·힌트·오답·자신감 기록으로 다음 일정을 바꿀 수 있도록 한다. 여러 번 같은 문제를 기억해 맞히는 것과 개념을 이해한 것을 구별한다. 복습 건수로 압박하지 말고 오늘 가능한 분량과 다음 계획을 보여 준다.

하이탑 등 교과서 밖 심화는 ‘더 깊이 이해하기’로 학생이 선택하여 연다. 수준·선수개념·예상 활동을 안내한다. 심화를 학습했다면 해당 형성평가를 해야 심화 이수로 인정한다. 열어 본 것과 읽기를 마친 것, 평가 통과를 별도 상태로 저장한다. 심화 미통과만으로 기본 필수 과정 전체를 무한히 막지 않는다.

## 6. 모의고사는 해설을 읽는 곳이 아니라 전략을 익히는 곳이다

실전 모드와 분석 모드를 나눈다. 실전은 시간·검토 표시·미응답·제출 확인을 제공하고 답과 해설을 먼저 노출하지 않는다. 분석에서는 문항의 출제 의도, 조건의 역할, 자료를 읽는 순서, 핵심 개념, 접근 전략, 계산·추론, 모든 선지 판단, 흔한 오답 경로, 전략의 적용 범위, 관련 선수개념, 재도전 계획을 제공한다.

각 대표 문항에는 기본 확인·조건 변형·표현 또는 맥락 전이의 **최소3개 새 유사문항**을 연결한다. 숫자만 바꾸는 경우뿐 아니라 추론 구조가 같은 다양한 자료를 만든다. 답의 유일성·단위·범위·그림·해설을 검증한 문항만 정식 평가에 쓴다. 자동 생성 직후 검증되지 않은 문제를 통과 평가에 내지 않는다. 원문과 `derivedFrom`으로 연결하고 학생에게는 ‘같은 전략을 적용하는 새 문제’임을 보여 준다.

경향성은 시험명·주관기관·학년·시행일·교육과정·수집 범위와 함께 표시한다. 2025·2026 고1 3월45문항은 중학교 선수 진단으로 구별한다. 몇 문항의 사례를 모든 수능의 법칙처럼 말하지 않는다. 현재 자료는 2028 실제 수능 문제가 아니라 공식 예시와 학력평가다. 새 시험을 추가할 때 분류와 전략 버전을 갱신하며 이전 시도와 당시 해설을 보존한다. 새 경향을 발견하면 근거 문항·확신 정도·기존 전략에서 바꿀 점·반례를 기록한다.

## 7. 영상과 그림

영상은 후속 제작을 위한 슬롯으로 구현한다. 각 슬롯에 `videoId`, 목표 개념, 구체적 장면, 길이 범위, 삽입 단계, 시청 전 질문, 시청 후 확인, 자막/대본, 제작 상태를 기록한다. 빈 슬롯에는 ‘여기에 [구체적인 영상]을 추가하면 좋아요’라는 검토용 안내 박스를 표시할 수 있어야 한다. 학생 공개 모드에서는 미제작 영상 때문에 진행이 막히거나 깨진 플레이어가 보이면 안 된다. 본문만으로도 해당 문항을 풀 수 있어야 한다. 자동 재생은 하지 않는다.

기존 교과서·하이탑 그림은 현 검토 버전에서 쓰되 **그림 바로 아래**에 실제 출처에 맞춰 `교과서 원본 이미지 · 재제작 필요` 또는 `하이탑 원본 이미지 · 재제작 필요`를 항상 표시한다. 색이 연해서 읽기 어렵거나 숨겨진 툴팁으로 대체하지 않는다. 자세한 재제작 프롬프트는 교재 제작 기록에 있으므로 학생 화면에 표시하지 않는다. 그림의 출처·ID·대응 문항·대체 상태를 데이터에 보존한다.

정확한 과학 도해는 SVG·표·그래프로 검증 가능하게 구현할 수 있다. 새 AI 장식 그림을 과학적 증거로 사용하지 않는다. 이미지 생성 시 프롬프트·도구·버전·원본 대응·검토 상태를 남긴다. 원본 참고 그림을 교체하면 관련 문제의 조건·정답·대체텍스트까지 재검토한다. 상업 공개 준비 상태는 애셋별로 관리하고, 단순히 출처 캡션을 지우는 것을 재제작 완료로 보지 않는다.

## 8. 계정·저장·결제 확장

React + TypeScript + Vite 프론트, Firebase Auth/Firestore/Storage 및 필요한 Firebase 서버 함수를 기본으로 구현하라. 버전은 구현 시 공식 문서와 호환성을 확인한 뒤 잠금 파일에 고정한다. 프론트는 Cloudflare Workers Static Assets로 GitHub에서 배포한다. Cloudflare와 Firebase는 별도 배포 대상이며 환경을 development/staging/production으로 분리한다.

Google·Microsoft·Apple·네이버·이메일 가입을 모두 설계와 실제 코드에 포함한다. 네이버는 Firebase 내장 provider라고 가정하지 말고 서버 OAuth 확인과 custom token 방식을 사용한다. API 키를 숨기는 것만으로 보안이 된다고 말하지 말고 Firebase Rules·서버 권한·App Check·호출 제한·UID 소유권 검증을 구현한다. 외부 공급자 설정 없이는 실서비스 인증이 완료됐다고 보고하지 않는다.

동일 이메일을 이유로 다른 계정을 자동 합치지 않는다. 최근 재인증과 양측 소유 증명을 거쳐 계정을 연결한다. Apple 비공개 이메일, 학교 Microsoft 계정 제한, 네이버 이메일 미제공도 정상 흐름으로 다룬다. 새로 가입했는지, 온보딩과 동의가 끝났는지, 연락 이메일을 확인했는지는 서로 다른 상태다. 개인정보를 최소 수집하며 미성년자 가입에 필요한 절차는 상세 명세에 따라 구현한다.

학습 위치·문항 시도·노트·작성 중 답안·활동 결과·요약과 수정 이력·복습 일정·영상 위치를 UID에 연결해 저장한다. 새로고침·로그아웃 후 재로그인·다른 기기에서도 검증한다. 자동 저장 상태와 실패/오프라인/충돌을 학생에게 알려 주고, 두 기기 수정본을 마지막 쓰기로 조용히 덮어쓰지 않는다. 학습자가 서버의 정답·숙련도·이용권을 직접 쓸 수 없어야 한다.

이용권(entitlement)을 학습 이력과 분리하고 서버가 판단하게 한다. 현재는 무료/초기 체험 접근 정책을 서버에서 발급한다. 다음 결제 서비스의 고객·상품·기간·상태 매핑이 들어갈 경계와 인터페이스만 준비한다. PG SDK·실결제·구독 청구·가짜 유료 잠금은 이번에 구현하지 않는다. 결제를 바꿔도 UID와 학습 이력이 유지되어야 한다.

## 9. 개발 순서와 완료 기준

먼저 자료 인벤토리와 내용 보존 대조표를 만든다. 그다음 중화 단원 한 묶음으로 선수 진단 → 충분한 본문 → 상호작용 → 평가 통과 → 노트 검토 → 복습 → 모의고사 분석까지 실제 저장을 포함해 끝까지 연결한다. 이 대표 경로가 성공하면 나머지31개 학습 묶음에 확장한다. 한 단원 시연본을 전체 완성본으로 보고하지 않는다.

앱 구조는 `content/`, `src/features/learn`, `assessment`, `review`, `notebook`, `exams`, `account`, `services`, `functions/`, `tests/`, `docs/`로 책임을 나누되 기존 저장소가 있다면 그 관례에 맞춘다. 본문·정답·출처·미디어·전략 버전의 스키마를 먼저 만들고 화면에 텍스트를 직접 박아 넣지 않는다. 비공개 정답과 해설은 제출 전 프론트 번들/HTML/대체텍스트/클라이언트 로그에 포함하지 않는다.

각 단계는 파일, 실제 기능, 검증 결과를 남긴다. 외부 공급자 키가 없더라도 Emulator·adapter·테스트·설정 안내까지 완료하고 필요한 값만 구체적인 설정 체크리스트에 남긴다. 실제 인증·배포·AI 호출이 안 됐는데 완료됐다고 쓰지 않는다. 이용자의 기존 파일을 임의로 삭제하지 않는다. GitHub 업로드나 외부 배포가 실행 환경에서 별도 승인을 요구하면 완성된 변경과 검증 결과를 준비한 뒤 필요한 마지막 승인만 요청한다.

최종 보고에는 실행 방법, 적용된 자료와 빠진 자료, 전체 문항/단계/도판의 보존 결과, 테스트 결과, 실제 인증 공급자 연결 상태, 배포 상태, 외부 설정 잔여 항목을 적는다. 이미 구현한 범위와 아직 필요한 문항 편집·영상 제작·그림 재제작을 명확히 구별하라. 첨부 `04_단계별개발과_인수검사.md`의 검사를 통과하기 전 전체 완성이라고 보고하지 말라.

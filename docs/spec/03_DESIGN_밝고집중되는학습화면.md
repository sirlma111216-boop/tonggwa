# 학생용 V1 디자인 명세

선정: **getdesign.md의 Mintlify Light**. 읽기에 적합한 밝은 문서 화면과 명확한 현재 위치 표시를 기준으로 골랐다. 브랜드 로고나 홍보 페이지를 복제하는 선택은 아니다. 아래 수치는 우리 학습 앱을 위해 새로 정한 값이다.

## 선택 근거와 다운로드

| 후보 | 이번 학습 앱에서의 판단 |
|---|---|
| Mintlify Light | 밝은 문서 표면, 절제한 초록 강조, 탐색·본문·보조 정보의 구분을 활용하기 좋다. 최종 선정. |
| Notion Light | 차분한 기록과 노트에는 적합하다. 필수 단계, 평가 행동, 설명과 정답의 위계는 별도 강화가 필요하다. |
| Airtable Light | 자료 목록과 기록 비교에는 유용하다. 장시간 개념 학습에서는 넓은 색 면과 카드 밀도를 절제할 필요가 있다. |

이는 화면을 비교한 설계 판단이며 학생 대상 피로도 실험 결과는 아니다. 기준일 2026-10-17.

| 용도 | 값 | 사용 규칙 |
|---|---|---|

| 본문 표면 | #FFFFFF | 긴 설명·문항·작성 영역 |
| 기본 글자 | #172B26 | 주요 본문과 제목 |
| 보조 글자 | #52635D | 출처·설명·단계 부연; 너무 작게 쓰지 않음 |
| 행동·현재 단계 | #087F68 | 제출·다음·활성 단계; 흰 글자 대비 검사 |
| 연한 초록 | #E7F5EF | 현재 개념·힌트 배경; 진한 글자와 함께 |
| 테두리 | #DCE5E0 | 1px 기본; 입력 경계는 더 진하게 |
| 주의 배경·글자 | #FFF4DA / #805600 | 조건·미저장·원본 그림 재제작 안내 |
| 오답 배경·글자 | #FDEDEC / #A52B23 | 잘못된 지점 표시; 색 외에 아이콘·문구 병행 |
| 탐구 보조 | #EAF1FA / #245E91 | 실험 자료·그래프 조건; 초록과 경쟁하지 않음 |

주요 행동색의 흰 글자 대비는 실제 계산으로 검사하고 WCAG AA 본문 기준을 만족하지 않으면 명도 조정한다. 원본의 밝은 민트색에 흰 작은 글자를 그대로 얹지 않는다. 모든 버튼을 초록으로 만들지 않는다. 한 단계의 우선 행동은 하나, 보조 행동은 선 또는 텍스트 버튼으로 구별한다.

한글 본문은 Noto Sans KR 또는 Pretendard처럼 라이선스가 확인된 한글 산세리프를 로컬 제공한다. 서체 파일과 라이선스를 함께 관리하고 임의 상용 서체를 복사하지 않는다. 본문 19px/1.75, 보조 설명16px/1.6, 작은 출처14px 이상, 단원 제목30px, 단계 제목24px를 기본으로 한다. 학생은 본문18~24px를 선택할 수 있다. 수식·위첨자·아래첨자·그리스 문자·마이너스·단위를 모두 렌더 확인한다. 수식은 이미지 대체보다 접근 가능한 수식 렌더링을 우선한다.

둥근 모서리는 표면12px, 입력8px, 작은 배지6px로 절제한다. 과도한 캡슐 버튼·유리 효과·반짝임·움직이는 배경·모든 카드의 큰 그림자를 쓰지 않는다. 강조는 정의 굵게, 조건 박스, 핵심 줄의 옅은 면, 표·그림의 연결선처럼 기능이 분명한 방법을 쓴다. 매 문장을 굵게 만들지 않는다.

## 넓은 화면을 쓰는 방식

| 화면 | 배치 |
|---|---|
| 1440px | 좌우24px, 단계208px, 간격20px, 중앙가변, 도움·노트300px |
| 1920px 이상 | 좌우32px, 단계232px, 간격24px, 중앙가변, 도움·노트340px; 전체 max-width로 가운데만 쓰지 않음 |
| 1024~1279px | 단계 목록을 접을 수 있는 레일로 전환; 중앙+도움의 두 영역. 도움을 펼칠 때 본문 최소 폭 확보. 필요하면 보조 패널을 서랍으로 열기 |
| 작은 휴대폰 | V1 정식 대상 아님. 입력 손실 없이 넓은 화면 권장 안내. 이를 위해 데스크톱 구조를 축소하지 않음 |

중앙 폭을 확보하더라도 긴 문단은 대략36~46rem 이내로 제어한다. 넓은 중앙 영역에는 설명과 입자 모형, 자료와 학생 작성 내용을 나란히 놓는다. 그래프는 가독성 있는 크기로 확대하고 국소 스크롤이 필요한 큰 표는 명확히 표시한다. 페이지 전체의 가로 스크롤은 만들지 않는다. 중요한 조건·단위·제출 버튼이 접히거나 영역 밖으로 밀리지 않아야 한다.

상단64px는 브랜드 가칭 ‘통합과학 학습실’, 과목 위치, 통합 검색, 저장 상태, 계정에 쓴다. 왼쪽 메뉴의 현재 위치는 색·세로선·텍스트로 나타낸다. 완료·진행 중·보충 필요·미학습은 다른 상태다. 오른쪽은 `개념 도움 / 내 노트` 탭, 평가 중에는 필요한 자료와 메모만 제공한다. 모의고사 실전에서는 정답을 드러내는 도움 기능을 끄되 제출 후 분석에 다시 연결한다.

## 핵심 화면의 실제 구성

### 첫 화면

첫 줄은 ‘이어서: 산과 염기가 반응하면 무엇이 남을까?’ 같은 실제 마지막 위치와 버튼이다. 해당 내용이 없으면 ‘선수개념부터 시작해 볼까요?’로 바꾼다. 생성 이미지의 높이는 첫 화면 약220~280px 이내, 전체 폭의 약1/3 정도를 시작 카드 옆에 둔다. 이어서 학습 카드가 이미지보다 중요하다. 아래에는 오늘 복습3~5항목, 실제 학습 지도, 지난번 내가 수정한 생각을 배치한다. 기능 없는 배너·가짜 친구 순위·성적 보장 수치 금지.

### 개념을 배우는 화면

현재 핵심 질문, 학습 목표1~2개, 꼭 알아야 할 선수개념 상태를 먼저 보여 준다. 본문에 ‘정의 → 현상 → 왜 그런가 → 조건 → 작은 적용’의 호흡이 드러나야 한다. 문단 중간의 도해는 연결되는 문장 가까이에 배치한다. 원본 도판 캡션은 바로 아래에 노출한다. 본문이 길면 학습 단계를 늘리고 내용은 유지한다. ‘자세히’ 뒤에 필수 정보를 모두 숨기지 않는다.

### 탐구 화면

왼쪽 중앙은 큰 조작 영역, 오른쪽 중앙은 ‘내 예상 → 관찰 기록 → 설명’이다. 조작값을 바꾸면 무엇이 변했는지 명확히 갱신한다. 모든 측정값은 단위·범위·이상화 조건을 표시한다. 계산하지 않은 수치를 임의 애니메이션으로 만들어 보여 주지 않는다. 초기화는 현재 활동만 되돌리고 이미 제출한 기록을 조용히 지우지 않는다.

### 평가·분석 화면

문제 자료와 응답 영역의 위계를 분명히 한다. 표·이미지는 원래 종횡비를 유지하며 확대 가능하게 한다. 제출 전에는 풀이를 보이지 않는다. 제출 뒤 `결과 → 나의 풀이와 다른 지점 → 선지별 판단 → 같은 전략 연습 → 복습 예약` 순서로 연다. 오답 표시는 작은 벌점처럼 표현하지 않고 다음 행동을 안내한다. 풀이 전체는 필요 시 이어 읽을 수 있으며 핵심 추론을 건너뛰지 않는다.

### 내 노트

본문과 작성 영역을 나란히 볼 수 있다. 저장 전·저장 완료·오프라인 대기·충돌을 문자로 표시한다. AI 검토는 제출한 버전과 연결하고 학생이 수정하는 동안 과거 결과로 새 글을 덮어쓰지 않는다. ‘바르게 쓴 내용’, ‘보완할 조건’, ‘내가 다시 고칠 부분’을 나누되 모든 피드백이 실제 학생 문장과 연결되어야 한다.

## 이미지 인계

`images/home-science-studio.png`는 내장 이미지 생성 도구로 만든 첫 화면 장식 이미지다. `images/이미지_제작기록.json`에 최종 전체 프롬프트와 용도를 남겼다. 새로운 교과서 도해를 대신하는 자료가 아니다. 기존 출판사 도판43개와 기존 생성 이미지3개, 이번 자체 과학 도해3종은 각각 교재의 출처·제작 기록을 따른다. 사용 위치별 alt를 작성하고 장식 이미지는 빈 alt로 처리한다.

## 화면 인수 조건

1440×900,1920×1080,1024×768 가로에서 첫 화면·긴 본문·큰 도판·수식·탐구·평가·노트·모의고사 분석을 실제 렌더한다. 주요 행동이 화면 밖으로 밀리지 않고 본문 확대200%에서도 조작 가능해야 한다. 키보드 포커스가 보이며 모달에 갇히거나 배경 입력으로 빠지지 않아야 한다. 명도 대비·도판 캡션·강조 위계·정보 위치를 확인하고 스크린샷을 개발 결과에 남긴다.

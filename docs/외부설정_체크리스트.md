# 외부 설정 체크리스트

값을 저장소에 넣지 않는다. 각 항목은 해당 서비스에서 직접 만든다.

## Cloudflare 자동배포 (GitHub Actions)

| 항목 | 어디에 | 상태 |
|---|---|---|
| `CLOUDFLARE_ACCOUNT_ID` | GitHub 저장소 Settings → Secrets and variables → Actions | 등록됨 (`gh secret set`) |
| `CLOUDFLARE_API_TOKEN` | 같은 곳. Cloudflare 대시보드 → Account API tokens → Create Token → **Edit Cloudflare Workers** 템플릿 | **사용자 등록 필요** (2026-10-20 확인) |

브라우저에서 등록하는 순서:

1. [Cloudflare Account API tokens](https://dash.cloudflare.com/?to=%2F%3Aaccount%2Fapi-tokens)에서 `tonggwa` Worker가 있는 계정을 선택한다.
2. **Create Token → Edit Cloudflare Workers** 템플릿을 사용한다. 이름은 예를 들어 `tonggwa-github-deploy`로 지정하고, 필요한 계정만 권한 범위에 포함한다.
3. [저장소 Actions secrets](https://github.com/sirlma111216-boop/tonggwa/settings/secrets/actions)에서 **New repository secret**을 누른다.
4. Name은 `CLOUDFLARE_API_TOKEN`, Secret에는 생성한 토큰을 입력하고 **Add secret**을 누른다. 토큰은 채팅·소스 파일·커밋에 넣지 않는다.
5. [Deploy 워크플로](https://github.com/sirlma111216-boop/tonggwa/actions/workflows/deploy.yml)를 수동 실행하거나 실패한 최신 실행을 다시 실행한다. 토큰 등록만으로 이전 실패 실행이 자동 재시작되지는 않는다.

공식 안내: [Cloudflare GitHub Actions](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/), [GitHub repository secrets](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets).

토큰을 만든 뒤 터미널에서:

```bash
gh secret set CLOUDFLARE_API_TOKEN --repo sirlma111216-boop/tonggwa
```

(붙여넣기 프롬프트가 뜨면 토큰 값을 입력). 이후 `git push origin main`마다 Actions가 빌드·배포한다. Actions 탭에서 결과를 확인한다.

배포 확인은 커밋·푸시 성공과 별도로 한다. 해당 커밋의 Actions 실행이 성공했는지 확인하고, 운영 사이트의 `/content/units/unit-1-1.json`에 개념 탐구실 revision `u11-concept-20261020-v1`과 12개 장면이 있는지 및 실제 수업 화면을 확인한다. 운영 사이트와 localhost는 서로 다른 배포본이며 학습 기록도 브라우저 origin별로 저장된다.

## Firebase (아직 미연결)

1. Firebase 프로젝트 생성(개발·운영 분리 권장).
2. Authentication: 이메일/비밀번호, Google, Microsoft, Apple provider 활성화. 네이버는 Functions의 custom token 흐름(명세 02 §2).
3. 웹앱 등록 후 설정값을 `.env`의 `VITE_FIREBASE_*`에 기입(`.env.example` 참고). 이 값은 공개 설정이며 비밀키가 아니다.
4. Authorized domains에 Cloudflare 배포 도메인 추가.
5. `src/services/auth/firebase.ts`, `src/services/progress/firestoreBackend.ts` 구현 후 `services/auth/index.ts`의 PROVIDER 전환.
6. Firestore Rules·Functions(채점·통과·복습)는 프론트와 별도로 배포한다.
